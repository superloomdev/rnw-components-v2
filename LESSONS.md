# LESSONS - contributor notes

One line per lesson: what failed, what worked, where to look. Every working session appends; the file is tidied once
before launch. Read this before building or converging a component; add to it when something cost more than an hour.
American spelling, no em dashes (the tracked-content gates grep the whole repo).

## Working method

- One session converges one family. Longer sessions lose their context and repeat the same probes; the fix is to end the session, not to try harder.
- Three focused guarded runs per failing test, each with a written hypothesis (part, property, upstream line or probe value, the cell or code line that changes). Then record the residual with `scripts/defects.js` and move on; a fresh session with a new hypothesis is cheaper than a fourth run.
- Every `node`, `npx` and `node --test` runs through `scripts/guard.js`; the guard's log (`_test/test-results/last-run.log`) holds the output and only its last 60 lines are read. Test logs, screenshots and pixel dumps in a conversation are what fills a context.
- A test file that does not exit in seconds is bisected by `--test-name-pattern`, never waited on: two React update loops (effect -> measure -> setState) were the 375 GB memory events; the jsdom harness now throws past 2000 commits in one render.
- Playwright: `workers: 1`, one browser run at a time, no `test.setTimeout` in a spec (G17), no `--timeout` flag on the command. `--grep "<describe> <Row>[ :/]"` with one space; ` . ` matches nothing.
- Build to the recipe and the probe (`__dev__/evidence/0160/recipes/`), never to a guess: nearly every fidelity failure in batches 12-14 was on the reference side (mount, selector, stylesheet), not in the component.
- A published template cell can be wrong. The B0 cells check compares the probe's upstream value with the built theme's value for every cell the recipe names; a mismatch is an amendment before the build.
- A fire-harness pattern that matches no test must fail, not pass: `_test/fire.js` looks for the indented inner result line and reports Playwright "No tests found".
- A guard test's allocation must stay below the outer guard's real ceiling: `GUARD_PROC_MB` applies to the whole `npm test` tree, and an outer guard at the same ceiling wins the kill because the inner guard's first sample lands a full interval after its spawn.
- A reparented orphan can enter the guard's `seen` set only while its parent still lives; macOS reparents before the exit event fires, so the orphan test's child idles 1.5 s before exiting.
- A killed orphan can still answer `process.kill(pid, 0)` for a moment after the SIGKILL (a zombie awaiting launchd's reap); probe it in a poll, not once.
- `fire.js` proves a row only from an indented result line on stdout: node tests need a `describe` wrapper for the indent, and the guard replays its tail to stdout as well as stderr so the recover run still sees it.
- `npm run batch` does not run `fire.js`; only `verify` does, so a fire-harness trap stays hidden until the milestone. Twenty-nine node test files had top-level `test()` calls (no indent) and two set assertions printed a 1000-line `deepEqual` diff that pushed the failure marker out of the guard's 60-line tail. A planted failure must print a bounded message: assert the first few missing and extra names plus the counts.
- The library gates do not see a host. At M5 the demo e2e (last run at 73 rows) found seven host-only defects in rows 74-126: a width written only to a ref (no re-render), a `flexBasis: 0` root that collapses in a column host, a decorative layer that was not `aria-hidden`, a hosted layer sized before the host reported its box. Run the demo e2e against the batch head at every batch close.
- The native walk found what both web verifies passed: a `.focus()` on a native ref that has none, a bare `document` reached on native, layout loops that grow a cell to 545503 px (a face size fed back into its own press target; a body that mounts or unmounts its scroller from its own layout), Android text inputs taller than their numeric `height`. Guard every DOM call by capability (`typeof document`, `typeof node.focus`), never measure a layout whose result changes that layout, and walk Android before a milestone.

## Harness and measurement

- Edit a JSON data file in place with its existing indent - the roster was re-indented whole once (slice 4 U9) and the diff swallowed the real change.
- Every element in a children array passed to `createElement` needs a `key`, including one rendered conditionally (`inline ? action : null`) - the structural `zero errors` gate catches it, the Node gates do not.
- A fire row whose `find` line moved is repointed with its `why` intact; `fire.js` reports "DID NOT RECOVER" when the named test is already red on clean code.


- A fixed-position layer (modal, menu, popover) is measured inside a transformed cell wrapper so the layer's containing block is the cell; the reference mount pins its fixed layer the same way (`oursHosted`), or the two pages measure different coordinate spaces.
- Cells that hold an open layer are settled with `settleLayout` before a screenshot; perceptual reopens reopen the state; pressed frames keep the press's focus (`settleBeforePress` opt-in).
- The perceptual gate compares the sample root's box on both pages (expanded to overflowing descendants), not the whole cell; a clipped layer at the cell edge otherwise dominates the percentage.
- Positioning hooks cap their re-measures at 8 per open cycle and warn once; an anchor that moves on every read is a harness defect.
- A hit-expander target that should be absent is asserted as `hitEl === null`, not as a size.
- The purity scan's `unit string` rule flags `'100%'` style literals (currently `actionable-notification.js:97`, `notification-parts.js:69`, `modal/reference.js:23`, `modal/reference.composed-modal.js:27`), so `npm run check` stays red on this tree until they go.
- Fidelity can fail where measure passes: the no-close action seat matched upstream geometry yet 28 cells were over the pixel budget, so a fidelity failure is a state-layer or color gap, not a position one.
- A `stage: true` cell body was squeezed to ~110 px by `.measure .grid`'s 160 px `grid-auto-rows` plus column-flex shrink; a fit made in that regime (Modal's header negative margin) was a squeeze artifact - the row spans in `harness/entry.js` and `reference-entry.js` hold the declared frame, so check a staged body's rendered height before trusting a staged fidelity number.
- jsdom drops the `borderWidth` shorthand from `style`; assert one long-hand side (`borderBottomWidth`).
- `docs:generate` regenerates every stale family page, not just the touched one; commit the regenerated pages with the unit.
- `scripts/defects.js` rebuilds `__dev__/DEFECTS.md` from the last `browser.json` only: a probe run overwrites it, and a later focused run drops earlier slices' rows. Run defects.js straight after the gate run, before any probe; carry earlier residuals in NOW.md until the closing `npm run batch` regenerates the full list.
- A part-dump probe must read colors from the innermost element holding the label text; reading the pressable root reported a label color the screen never showed (slice 3 U5).
- A clean `_test` install (node_modules and lockfile removed) also drops Playwright's browser binary: reinstall chromium through the guard before the first browser run, or every browser test fails at `browserType.launch` (slice 6 U5).
- Carbon's in-list Tag draws 32, not its `md` 24: `ContainedListItem.js:39-45` wraps the action in `LayoutConstraint` (min `sm`), which sets `--cds-layout-size-height-min` to the global `sm` size (32) on the wrapper, and the tag's `clamp(min, 24, 24)` lets the minimum win (`styles.css:2704,12742,10750`). Read the React wrapper and the compiled CSS, not only the component SCSS; the data already existed (`size.size_small`, slice 6 U6b).

## Component patterns

- A low-contrast outline is an inset `box-shadow`, not a border: a border changes the box and shifts every inner measurement by its width.
- Inline widths that the reference derives from its container are `100%` capped by the family's width cell (`notification_inline_width`), never a fixed width; the toast keeps the fixed cell.
- An overlay heading that the reference pulls up over its label is a token-derived negative margin (header space minus heading line height, minus the label line height and gap relative to the body padding); never a measured constant.
- Separators in a breadcrumb stay unless both `last` and `noTrailingSlash` hold; the reference's rule, not the obvious one.
- Composition props (`api.composition`) exist only for a composing parent (breadcrumb overflow trigger size, icon offsets, menu offset, focus underline); a prop with no composing consumer is deleted.
- Modal width and max height are ratios of the layer space (`control.dialog_width_ratio[_xs|_sm|_lg]`, `control.dialog_height_ratio[...]`) with the form variants holding the compact values; no breakpoint read in a component.
- Submenus dismiss against their parent (`dismissRootRef`); a menu's own outside-press handler must not close its parent.
- Values a template never specifies come from the reference's own scale and are marked `superloom_decision`; a derived number without an upstream line is a defect (D21c).
- Enum values are named by behavior or shape (`floating`, `ripple`, `grows`), never by a design system; a value no shipped template picks stays when a unit test and the enum-render gate cover it (a brand layer may pin it).
- A CSS flex item's automatic minimum is its min-content (Carbon modal footer buttons: `flex: 0 1 50%` plus the 15/63 padding); react-native-web defaults `minWidth: 0`, so reproduce it as `minWidth: <ratio>%` + `flexShrink: 0`.
- A composing parent recolors a focus ring through `ctx.focusRing(..., { ringLeaf })` (outline, border and inset shadow together); `Button` `focusRingGap: false` drops the page-color line. Overriding `outlineColor`/`borderColor` after the call misses the inset shadow.
- A component wrapper inside a row-flex cell body is only as wide as its content: a child's `width: 100%` (Carbon `inline-size: 100%`) needs the wrapper itself at `100%` too (ActionableNotification trap wrapper, slice 3 U8).
- Carbon notifications apply their inverse button themes only `:not(--low-contrast)`: a low-contrast action is the plain ghost/tertiary kind in every state, so pass it no recolor leaves.
- A `reference.*.js` for a `no_reference` member breaks the harness: `reference.mount is not a function` renders at gate time; no-reference members ship no reference file.
- A standalone reference needs its `parts` map before any gate run; grep for `parts: Object.freeze` after any scripted insert - a replace-pattern miss once failed silently.
- `docs.test.js` hard-codes every sample `FRAME` as a `name:width` list; adding a `FRAME` to a sample means adding its entry there.
- The gate reader (`harness/page.js` `readParts`) takes the first match of a part's selector; `all: true` does not change what a gate reads. Narrowing a selector fixes a pairing only if the first match changes, so check that the reported value moved before crediting a selector hypothesis (slice 6 U6: ContainedList `tags` read 24 ours vs 32 upstream before and after the narrowing).
- Read the pixels before the colors: `FIDELITY_DIFF_DUMP=<dir>` (+ `FIDELITY_DIFF_PROBE=1` for computed styles) writes each compared pair, its diff and `frame.json`; `_test/scripts/diff-probe.js <dir>` gives diff bboxes, colors and the parts at each centre. In one pass it found four causes three color-hypothesis rounds had missed: a toast action 8 px low, a fixed-width Callout band whose action fell outside the crop, an upstream rest frame that was focused, and a target that could not take focus (slice 6 U8-U9).
- Upstream ActionableNotification focuses the document's first action button on every mount (`Notification.js:449`, `hasFocus` defaults true), so its rest frames are focused. The reference mount wraps it in a component whose mount effect blurs that button.
- An interaction target must be the node that takes focus (the Pressable), not a plain View inside it. Focusing a View does nothing and raises no error, so the focus frame is drawn without its ring.
- Never pipe a gate command into `tail` when its exit code matters: `npm run check -- X | tail` reports the pipe's status, so a red test read as a pass for two units (slice 6b U2-U3). Read the guard log's summary line, or use `set -o pipefail`.
- A Carbon icon button inside a container takes the container's layout size (`_button.scss:113,248` `layout.size('height')`), clamped by any `LayoutConstraint` around it. In an `md` ContainedList it is 40, not its own default 48. Map the parent's size onto the child's `size` prop (slice 6b U8).
- A `fill: true` Button (`flexBasis: 0`, `flexGrow: 1`) inside a column wrapper gets no height from its label, so scaled text overflows it. Its wrapper must be a row so the flex basis acts on the width and the label sets the height (slice 6b U9). A sample FRAME body is `position: relative`, so a member's absolute parts anchor to it as they would to their parent.
- A part upstream paints outside the component's box by design (Carbon list markers `_list.scss:64-96`, the breadcrumb overflow icon `_breadcrumb.scss:162-167`) is not a bounds defect and not a reason to move the part: the sample declares `FRAME.hang` and the body reserves the room, as a host must; the reference `body` carries the same `hang` so the crop compares the part on both pages.
- Before calling a contrast failure the component's, read the reader's `stack=[...]`: `div[role=alertdialog]=rgb(224,224,224)` named the default template's own fill (`notification_background_*` at ramp step 2 under `interactive`), a template data fix, while `stack=[]` on a standalone inverse label meant the sample lacked its band (`wrappers`), not that the component was wrong.
- A marker positioned with a physical `left` fails the rtl bounds pass while `paddingInlineStart` reserves the other side: upstream's `inset-inline-start` is React Native's logical `start`.
- A native walk that returns no report for any template is not a layout loop until the device log says so: the M5 iOS zero-report was `dyld: Symbol not found: _OBJC_CLASS_$_RCTStatusBarAppearance` - a lockfile refresh had moved `expo-modules-core` to 58.0.30 while `react-native` stayed pinned at 0.88.0. Read the crash `.ips` before reading the components (slice 7c U2).
- A native ref has `focus`, `blur` and `measure` and nothing else; `contains`, `querySelector*`, `getBoundingClientRect`, `addEventListener` and every `document.`/`window.` read throw on a device. Every such reach lives in `behaviors/dom.js` behind a capability check and the purity scan forbids a raw one; the library's own web tests cannot see this class, only a native walk can (7c U3).
- Yoga sums the flex bases of a row whose width is indefinite; three segments at `flexBasis: 0` make a shrink-to-fit row 0 wide, and a zero-wide `Text` measures a glyph per line (height 16639). CSS gives the items' max-content sum. `ctx.useSegmentBasis` hands native segments the mean of their natural widths as the basis (7c U4).
- `flexGrow: 1` on a component root grows along the host's main axis: in a row host it fills the width (what upstream's `width: 100%` meant), in a column host under a native ScrollView Yoga grew it to 492714 px. Translate `width: 100%` as `width: '100%'`; a percentage is a Yoga value, not a CSS unit (7c U5, plan D56).
- The walker reports the layout that stopped moving (500 ms quiet), not the first one: native lays a cell out more than once. Metro does not watch a `file:`-linked library, so a probe edit needs `simctl terminate` + relaunch; a Release build embeds the bundle, so a proof walk needs `expo run:ios --configuration Release` again (7c U4-U5).
- A `flexWrap: 'wrap'` row on native takes its line height from each item's size at its flex basis, not after growth: a `flexBasis: 0` details box whose Texts break a glyph per line at width 0 leaves the frame 245-421 px tall while the box itself reports 66. Making the frame `nowrap` with basis `auto` did not move InlineNotification and regressed the web toast states; the mechanism needs a minimal Yoga probe screen before the next attempt (7c U5-B, open).
- Measured rule (7c U5-C probe, `__dev__/evidence/0160/m5/ios-local-u5c/`): a row whose width is indefinite (a host with only `maxWidth`, or a `%` width under such a host) is sized by Yoga from the sum of its children's flex bases plus margins, where CSS uses their max-content; a `flexBasis: 0` subtree contributes 0, is laid out 0 wide and stacks its Texts one per line (literal notification band: frame 64 = 3 + 13 + 0 + 48 on iOS, 288 on web). `nowrap`, dropping the `%`, or basis `auto` on one level do not cure it while a deeper level keeps basis 0. `flexBasis: 0` + grow is native-safe only under a definite main size or a floor; translate upstream's `min-inline-size` too. A child's `flexGrow: 1` in an indefinite column under a ScrollView is content height (probe c3), so a runaway column height has another cause.
- `Button` `fill` is `flexBasis: 0` + grow: under a row whose width is indefinite it falls to its floor on native (the inline notification action 104 vs 138), and a narrower part elsewhere in a band gives its text more room and a shorter native height (Callout 66 vs 120). Fill only where the seat is definite (the toast's `flexBasis: 100%` seat); a content-width action is upstream's `inline-size: max-content` (7c U5-F).
- A grower is the container's to ask for: a standalone `flexGrow: 1` box is content height in CSS but native Yoga stretched it against its host (ModalBody 9849 px around 20 px); upstream's growth is the dialog grid's `1fr` row, so the dialog passes an internal `fill` (7c U5-H). A minimal probe of the same style did not reproduce it - probe the real chain before generalising.
- A row that fills its container (`inline-size: 100%`, a block-level flex line) needs a sample FRAME: in a shrink-to-fit cell the web width comes from the browser (an `<input>`'s default 149 px intrinsic width) and native wraps a line whose rounded items (iOS text thirds: 243.34) exceed a shrink-wrapped cap (243.33) (7c U5-I; ContainedList, BreadcrumbSkeleton).
